# RM75 Training V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Correct the RM75 timeout reward, distance pressure, exploration schedule, and hidden actuator-target state before a new long PPO run.

**Architecture:** Preserve the cumulative position-servo target because it provides stable gravity holding, but expose the seven-dimensional tracking error `q_target - q` in observations so the policy sees the controller state. Add an explicit terminal timeout penalty, strengthen the distance penalty, and bound exploration with a reproducible standard-deviation schedule from `0.20` to `0.08`. Leave learning-rate scheduling, horizon, checkpoint selection, and curriculum unchanged.

**Tech Stack:** Python 3.10, NumPy, Gymnasium, MuJoCo, PyTorch, unittest, TensorBoard.

**Spec:** User-approved items 1-4 and selected implementation for item 8 from the 2026-09-30 RM75 one-million-step review.

## Global Constraints

- Set `timeout_penalty=25.0` and apply it only when the horizon is reached without success or collision.
- Set `dist_weight=0.1`; keep `progress_scale=50`, `success_bonus=100`, and `collision_penalty=75` unchanged.
- Schedule effective action standard deviation linearly from `0.20` to `0.08` over the existing number of PPO iterations.
- Set `ent_coef=0.0001`.
- Do not change learning-rate annealing, the 1024-step horizon, checkpoint behavior, or target curriculum.
- Preserve cumulative `q_target` control and append `q_target - q` to the observation; final RM75 observation shape is `(28,)`.
- Existing 21-input RM75 checkpoints are incompatible with the new 28-input Agent and must not be used for resumed training.
- Tests use standard-library `unittest`; do not create Git commits on the user's behalf.
