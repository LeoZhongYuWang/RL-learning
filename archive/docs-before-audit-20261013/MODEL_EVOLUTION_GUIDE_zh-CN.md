# UR5 到 RM75 强化学习项目演进与设计审查

本文不是只列出“改了哪些参数”，而是回答五个问题：

1. 原项目为什么不能直接稳定地训练出现在这些模型？
2. UR5-V3、RM75-V3、RM75-V4 和位姿模型之间到底改变了什么？
3. 每项改变解决了什么问题，有没有训练证据支持？
4. 为什么代码从几百行增长到几千行？这些代码是否都属于 PPO 算法？
5. 哪些设计可以迁移到以后其他机械臂强化学习项目，哪些不能照抄？

> 审查基准：Git 提交 `afa1ccf`（`Final Setup`）中的代码作为“原项目基线”；当前工作区作为最新实现。训练数据来自本地 TensorBoard event、W&B 配置、本地模型和 `best_metrics.json`。本文不把训练滚动成功率当成独立评估成功率。

## 1. 先给结论

### 1.1 当前几个模型分别代表什么

| 模型                 | 任务                    | 观测/动作 | 现有结果                                   | 正确结论                                 |
| -------------------- | ----------------------- | --------: | ------------------------------------------ | ---------------------------------------- |
| 原项目 UR5           | 随机点到达              |    19 / 6 | 原始实现，没有可靠独立评估                 | 是可运行的教学基线，不是完整训练系统     |
| UR5-V3               | 随机点到达              |    19 / 6 | 训练末段滚动成功率约 81%，碰撞率约 19%     | 已学会点到达，但安全性和独立评估仍不足   |
| RM75-V3              | 随机点到达，含自碰撞    |    28 / 7 | 训练末段滚动成功率约 79%，碰撞率 0%        | 成功率接近 UR5，安全性明显更好           |
| RM75-V4 high-success | 随机点到达，含自碰撞    |    28 / 7 | 固定 100 种子最佳评估成功率 84%，碰撞率 0% | 当前最可靠的 RM75 点到达模型             |
| RM75 位姿系列        | 随机位置 + 随机切入方向 |    34 / 7 | 当前仍在课程早期阶段，最终严格成功率为 0%  | 已学到部分阶段目标，尚未完成最终位姿任务 |

最重要的判断是：

- **RM75-V4 已经证明点到点任务的环境和算法设计有效。**
- **位姿任务不是点到点任务“多训练一些步数”就自然得到的结果。**它增加了方向观测、联合成功条件、可行目标采样和课程学习，是一个新的 MDP。
- **当前位姿模型的 `success_rate` 是当前课程阶段成功率，不等于最终 5 cm/20° 或过去的 5 cm/15° 严格成功率。**必须同时看 `strict_success_rate`。
- 代码增长主要来自多机器人兼容、独立评估、断点续训、课程控制、指标和容错，不是神经网络变得更大。Actor/Critic 仍是两层 64 单元的 MLP。

### 1.2 改动是否总体合理

总体合理，并且分为三种层级：

- **必须有：** 合法的机器人模型、正确的关节/执行器顺序、有界动作与正确 log-prob、任务可观测性、碰撞定义、严格成功条件、固定种子独立评估、可恢复 checkpoint。
- **有证据支持：** UR5 动作/奖励稳定化、RM75 自碰撞、RM75-V3 里程碑和探索计划、RM75-V4 均匀采样与最佳模型评估。
- **仍属实验设计：** 位姿奖励各权重、课程阶段阈值、晋级/回退比例、每阶段需要多少步。这些不能仅凭代码合理性证明有效，必须由固定评估结果验证。

## 3. 原项目基线：它有什么，缺什么

### 3.1 环境定义

原始 `env.py` 已经包含：

- UR5 六轴模型、桌面、起点和随机目标点；
- 位置/速度/末端位置/目标/碰撞组成的 19 维观测；
- 每回合最多 1024 个环境 step；
- 每个环境 step 内执行 10 个 MuJoCo 物理子步；
- IK、位置/速度/力矩三种控制分支；
- 成功、碰撞、时间、距离和进度奖励。

但存在几个会直接影响 PPO 学习的问题：

1. **策略分布与动作物理单位混在一起。**环境动作直接是 `[-0.05, 0.05] rad`，而原 PPO 的高斯分布初始标准差是 1，绝大多数采样要靠 `ClipAction` 静默截断。PPO 计算概率的是截断前动作，环境执行的是截断后动作，概率比与真实行为不一致。
2. **进度奖励在接近目标时被距离作除数放大。**原公式为 `10*(d_prev-d)/d`，当 `d` 很小时，同样的毫米级变化会得到过大奖励，也更容易产生目标附近摆动和高方差价值目标。
3. **每次 reset 重新编译 MJCF。**桌子固定时没有必要，降低 SPS，且把结构随机化与状态随机化混为一谈。
4. **IK 顺序有逻辑漏洞。**`start_pos` 在 IK 判断之后才赋值，因此首次 reset 时“用 IK 到起点附近”的分支实际可能不执行。
5. **原 PPO 只有最终权重。**中断后不能完整恢复优化器、随机数、global step 和课程状态，也不能自动保留独立评估最好的模型。
6. **可视化只支持 UR5 且默认随机采样动作。**模型维度变化后会直接出现 state_dict size mismatch。

### 3.2 原始 PPO 参数

| 参数                |                原值 | 风险                                                 |
| ------------------- | ------------------: | ---------------------------------------------------- |
| learning rate       | `3e-4` 并衰减到 0 | 对这个连续控制任务更新偏快，训练末端完全失去学习能力 |
| rollout steps       |                1024 | 每次估计样本较少                                     |
| minibatches         |                  32 | 每个 minibatch 较小                                  |
| update epochs       |                  10 | 同一批数据反复更新较多，易造成过大策略漂移           |
| entropy coefficient |                0.01 | 对精确到点动作可能长期过度探索                       |
| target KL           |                  无 | 没有基于 KL 的提前停止保护                           |
| initial action std  |                 1.0 | 与小动作范围严重不匹配                               |

这些不是说 CleanRL PPO 本身错误，而是默认值和动作接口没有针对当前机械臂任务形成一致的控制契约。

## 4. 原项目到 UR5-V3：具体改了什么

### 4.1 动作接口：从“弧度动作”改为“归一化策略动作”

当前实现：

```python
action_space = Box(-1.0, 1.0, shape=(6,))
joint_delta = 0.02 * clip(action, -1, 1)
q_target = clip(q_target + joint_delta, joint_limits)
```

含义：策略输出的 `1.0` 不是 1 rad，而是本 step 的最大关节目标增量 `0.02 rad`。因此：

- 神经网络始终在统一的无量纲空间学习；
- 环境单独负责把动作转成机械臂物理量；
- 以后换机械臂时可以保留策略接口，只调整 `action_scale`；
- `q_target` 仍会累计，所以安全性不仅由单步 0.02 决定，还必须有 joint limits、碰撞终止和最终实机速度限制。

PPO 同时改成 **Tanh-squashed Gaussian**，采样动作天然在 `(-1,1)`，并在 log-prob 中加入 Tanh 雅可比修正。这个改动是算法正确性修复，不只是“让动作小一点”。

### 4.2 重置：模型只编译一次

现在在 `__init__` 中构建 `MjModel/MjData`，reset 只做：

1. `mj_resetData` 清空状态；
2. 用 seed 重建环境 RNG；
3. 给 IK 初值加入 `N(0, 0.02)` 关节噪声；
4. 用 IK 把末端放到统一起点附近；
5. 把当前位置锁存为位置执行器 `q_target`；
6. warmup 若干物理子步。

随机初始关节噪声不需要重新编译模型。重新编译只适用于拓扑、geom 数量或 MJCF 结构真正改变的情况。

### 4.3 UR5-V3 奖励

当前点任务可概括为：

```text
r_t = 50(d_{t-1} - d_t)
      - 0.02 d_t
      - 0.01
      - 70 · I(collision)
      + 100 · I(success)
```

相对原项目的变化：

| 项目         |              原项目 |            UR5-V3 | 原因                             |
| ------------ | ------------------: | ----------------: | -------------------------------- |
| 进度公式     | `10*(d_prev-d)/d` | `50*(d_prev-d)` | 去掉近目标奇异放大，形成稳定势差 |
| 持续距离惩罚 |          `-0.5*d` |       `-0.02*d` | 避免每一步绝对距离惩罚主导总回报 |
| 碰撞惩罚     |                 -10 |               -70 | 让碰撞捷径明显劣于安全接近       |
| 成功奖励     |                +100 |              +100 | 保留清晰终点信号                 |
| 时间惩罚     |          -0.01/step |        -0.01/step | 仍鼓励更少步骤完成               |

#### 为什么势函数进度不会鼓励来回摆动

若进度项为 `k(d_{t-1}-d_t)`，连续多步求和约为：

```text
k[(d0-d1) + (d1-d2) + ... + (d_{T-1}-dT)] = k(d0-dT)
```

向目标移动后再退回，正负进度会抵消；再加上每步时间惩罚，来回摆动只会更差。`gamma=0.99` 时不是数学上完全相消，但仍比除以当前距离的旧公式稳定得多。

### 4.4 PPO 稳定性参数

UR5-V3 使用的主要参数：

| 参数                |   原项目 |      UR5-V3 |
| ------------------- | -------: | ----------: |
| learning rate       | `3e-4` |    `1e-4` |
| rollout steps       |     1024 |        2048 |
| minibatches         |       32 |          16 |
| update epochs       |       10 |           5 |
| entropy coefficient |     0.01 |       0.001 |
| target KL           |       无 |        0.02 |
| action std          |      1.0 | 初始约 0.30 |

影响：单次更新更保守、每次 rollout 信息更多、探索噪声与动作尺度匹配、KL 过大时提前停止更新。它们影响的是学习稳定性，不直接保证策略一定成功。

### 4.5 训练证据

- UR5-V3：1,998,848 steps；末段最近窗口成功率约 **81%**，历史峰值约 94%；末段碰撞率约 **19%**。
- 这说明点到达能力已形成，但“成功率提高”和“碰撞安全”没有同时达到理想水平。
- 这是训练分布内的滚动指标，没有同版本保存的固定 100 种子独立评估，因此不能把 81% 当作严格泛化结论。

## 5. UR5-V3 到 RM75-V3：不是只把 XML 文件名换掉

### 5.1 机器人模型与控制契约

RM75 迁移包含：

- 将厂家 URDF 和 STL 复制到项目，修正 ROS `package://` 路径；
- 自动转换结果 `rm75_imported.xml` 与人工审核版 `rm75.xml` 分离；
- 明确 `joint_1 ... joint_7` 和 `joint_1_pos ... joint_7_pos` 的顺序；
- 按 URDF 使用 RM75 关节范围和力矩范围，而不是照抄 UR5；
- 添加 `ee_site`、home keyframe、MuJoCo 位置执行器；
- 环境启动时验证 7 关节和 7 执行器的同序映射。

这是迁移中最必要的一层。若关节顺序错一位，PPO 仍可能运行，但“动作第 i 维控制第 i 关节”的假设已经失效，训练结果没有物理意义。

### 5.2 观测从 19 维变成 28 维

```text
UR5: q(6) + qd(6) + ee(3) + goal(3) + collision(1) = 19

RM75: q(7) + qd(7) + (q_target-q)(7)
      + ee(3) + goal(3) + collision(1) = 28
```

RM75 增加 `q_target-q` 是因为位置执行器跟踪目标不一定等于当前关节状态。策略知道“已发出的目标”和“机械臂实际位置”之间的误差后，能区分：

- 机械臂尚未跟上前一动作；
- 当前确实需要继续增加目标；
- 执行器饱和或动态滞后。

代价是旧 UR5 权重不能载入 RM75：第一层从 19 维变为 28 维，输出从 6 维变为 7 维。

### 5.3 Seed 控制的摩擦随机化

桌面结构不重新编译，只在 reset 中由环境 RNG 修改 `model.geom_friction`。同一个 seed 会复现：

- 初始关节噪声；
- 目标位置；
- 桌面摩擦。

这属于轻量 domain randomization。它对纯空中到点任务影响不大，但为以后接触/抓取任务提供可复现的物理扰动接口。

### 5.4 自碰撞

RM75 环境缓存 base、7 个 link、桌面和地面的 geom ID：

- 机器人碰桌或非 base 部件碰地：碰撞；
- 非相邻 robot link 接触：自碰撞；
- 相邻 link 在关节连接处的结构接触：白名单忽略；
- 碰撞立即终止并扣分。

UR5-V3 没有这套明确的 RM75 自碰撞分类。加入它会缩小可行策略空间，通常让早期成功更难，但避免学出穿过自身的仿真捷径。对最终要迁移到实机的策略，这是必要约束。

### 5.5 RM75-V3 奖励与探索

相对 UR5-V3，RM75-V3 增加：

- 超时终止惩罚 `-10`；
- 首次进入 20 cm：`+5`；
- 首次进入 10 cm：`+15`；
- 里程碑每回合只触发一次，避免反复跨阈值刷分；
- action std 前 25% 保持 0.30，再衰减到 0.12；
- entropy coefficient 降到 0.0001。

里程碑用于解决“成功信号稀疏”：即使还没进 5 cm，也能区分到 20 cm、10 cm 的策略。它不是最终目标替代品，因为只有达到 5 cm 才获得 +100 并终止成功。

### 5.6 UR5-V3 与 RM75-V3 结果对比

| 指标               |       UR5-V3 |    RM75-V3 | 解读                           |
| ------------------ | -----------: | ---------: | ------------------------------ |
| 训练步数           |    1,998,848 |  1,998,848 | 步数可比                       |
| 末段滚动成功率     |          81% |        79% | 点到达能力接近                 |
| 历史最高滚动成功率 |          94% |        81% | UR5 峰值更高，但不代表稳定泛化 |
| 末段滚动碰撞率     |          19% |         0% | RM75 安全性更好                |
| 任务约束           | 无新增自碰撞 | 明确自碰撞 | RM75 的问题更严格              |

结论：RM75-V3 并非“比 UR5 差 2%”，而是在更严格碰撞规则下达到了相近成功率。不过两者的运动学、可达域和目标分布并不完全等价；正式跨机器人比较仍应使用两者共同可达的同一目标集合和相同种子独立评估。

## 6. RM75-V3 到 RM75-V4 high-success：哪些优化真正得到验证

RM75-V4 不增加任务难度，目标是让同一个点到点任务稳定超过 UR5-V3。

### 6.1 改动

| 改动       | V3                  | V4                             | 作用                             |
| ---------- | ------------------- | ------------------------------ | -------------------------------- |
| 初始化     | 随机初始化          | 随机初始化                     | 避免被旧局部最优限制             |
| 目标采样   | 曾实验 hard mixture | uniform 全框均匀               | 避免过采负 Y/远 X 后遗忘其他区域 |
| 碰撞惩罚   | 75                  | 45                             | 允许探索靠近障碍，不取消碰撞终止 |
| 总步数     | 2.0M                | 2.5M                           | 给全区域策略更多数据             |
| action std | 0.30→0.12          | 0.30→0.10，前20%保持          | 后期更精细                       |
| 固定评估   | 无完整 best 机制    | 每 200k、100 个固定种子        | 区分训练噪声和真实改进           |
| 保存       | 最终权重            | latest checkpoint + best model | 可恢复且不会丢掉中途最佳策略     |

### 6.2 结果

- 训练末段滚动成功率：**88%**，滚动峰值 92%；
- 最佳固定 100 种子评估：**84% success**；
- 最佳固定评估碰撞率：**0%**；
- 最佳平均最终距离：**6.58 cm**；
- 最佳点位于 global step **2,000,896**，不是最终一步。

这证明 best-model 机制不是冗余：训练结束时策略不一定就是整个训练过程中最好的策略。

#### 为什么降低碰撞惩罚没有造成更高碰撞率

碰撞仍然会终止回合；`-45` 仍远大于普通单步奖励。调整的是“探索时一旦碰撞的灾难程度”，不是允许碰撞。过强惩罚会让策略宁愿停住也不敢接近目标；适度降低后，探索更充分，最后独立评估仍为 0% 碰撞。这个结论只对当前仿真和目标区间成立，不能直接作为实机安全参数。

## 7. 点到点到随机位姿：为什么必须重新定义任务

### 7.1 新任务不是完整抓取

当前位姿任务要求：

- 末端到随机目标位置；
- 末端局部 `+Z` 轴与随机目标切入方向对齐；
- 同时满足位置和角度阈值才成功；
- 不包含夹爪闭合、物体接触、抓稳、抬升和实机控制。

因此它准确的名称是“随机位置 + 随机切入方向的末端位姿到达”，不是完整随机点抓取。

### 7.2 观测从 28 维变成 34 维

位姿任务在 RM75 点任务的 28 维基础上加入：

```text
当前末端工具轴(3) + 目标切入方向(3) = 6
```

总计 34 维。若目标方向不在观测里，同一个位置状态对应多个不同正确动作，策略无法判断本回合要求哪个方向。这是可观测性要求，不是为了让网络“知道更多”而随意加特征。

### 7.3 随机方向的定义

以世界坐标 `-Z` 为圆锥中心轴：

- `tilt`：目标方向偏离 `-Z` 的夹角；
- `azimuth`：绕 `-Z` 一周的方位角；
- 方向向量由两者生成，而不是把一个角度写死在代码里。

可视化中的方向线把抽象的三维向量显示为目标点附近的黄色/绿色方向标记，便于观察“位置到了但角度没到”的失败。

### 7.4 可行性过滤

随机位置和随机方向组合不一定都可达。环境先在 scratch `MjData` 上执行位置+方向 IK，并检查碰撞；失败则重新采样，最多若干次。它的作用是避免把大量物理不可达任务混入训练，让失败更可能来自策略，而不是任务生成器。

注意：IK 可行只说明存在一个满足约束的关节解，不保证 PPO 从当前起点一定容易找到该路径。

## 8. 位姿奖励为什么这样设计

### 8.1 联合归一化误差

当前阶段的误差先除以该阶段成功阈值：

```text
e_pos = distance / active_distance_threshold
e_dir = angle_error / active_angle_threshold
```

这样米和弧度变成可比较的无量纲量；`e<1` 表示该项进入当前阶段阈值。

当前 V7 代码使用：

```text
smooth_max = smoothmax(e_pos, e_dir)
E_pose = 0.5*smooth_max + 0.4*e_pos + 0.1*e_dir
```

其中 smooth max 近似取位置误差和方向误差中较差的一项，但保持连续梯度。使用纯 `max` 时，如果位置误差较大，短期改善角度完全不改变奖励；smooth max 可以让两项都有学习信号。

### 8.2 当前位姿奖励

```text
r_t = 5(E_{t-1} - E_t)
      - 0.03 E_t
      - 0.01
      + one-shot pose milestones
      - collision penalty
      - timeout penalty
      + success bonus
```

位姿任务不再额外叠加点任务的 `-dist_weight*distance`，否则同一个位置误差会在综合误差和距离项中重复计算。

设计含义：

- `E_{t-1}-E_t`：鼓励本 step 让联合误差变小；
- `-0.03E_t`：即使暂时没有改善，也持续偏好误差更小的状态；
- `0.4*e_pos`：针对历史实验中“方向变好但位置退化”的瓶颈加强位置；
- one-shot milestones：只有位置和方向一起进入较宽阈值才奖励，避免只优化其中一项；
- success 仍要求位置与角度同时达标。

### 8.3 当前课程成功与最终严格成功必须分开

环境同时计算：

- `success`：当前课程阶段的阈值，用于终止、奖励和晋级；
- `strict_success`：最终任务阈值，不受当前阶段影响；
- `position_success` / `direction_success`：最终单项阈值；
- `ever_position_success` / `ever_direction_success`：整回合曾经达到过单项阈值；
- `simultaneous_success`：位置和方向同一时刻成功。

如果 Stage 2 的成功条件是 10 cm/35°，达到它会得到 `success=1`，但并不代表已经达到最终 5 cm/20°。因此报告最终能力时绝不能只展示 `charts/success_rate`。

### 9.1 为什么成功率会升高后下降

常见原因不是单一的“网络忘了”：

1. **课程分布变化：**目标区域扩大、最大倾角增加、阈值收紧，成功率定义也改变，曲线会产生真实断点。
2. **on-policy 分布漂移：**PPO 每次使用最新策略采样，少量不利更新会改变后续数据分布。
3. **训练窗口抽样噪声：**最近 100/200 回合的目标难度不同，尤其随机姿态任务方差很大。
4. **奖励权衡：**方向改善可能以距离退化为代价，反之亦然；只看总 return 会掩盖这种交换。
5. **探索与学习率过大：**进入精确阶段时若重新放大 std 或 LR，会破坏已有精细动作。项目已移除阶段切换时主动重置探索，并保持 LR 单调。

判断“正常波动”还是“策略退化”的方法：训练滚动曲线下降不一定是退化；若固定种子 `eval/success_rate`、`mean_min_distance`、`mean_min_angle` 同时持续恶化，才是强证据。

## 11. 可视化脚本为什么也要改

原脚本存在三个根本限制：

1. 写死 UR5 环境；
2. 只接受 agent state_dict，不理解完整 checkpoint；
3. 即使 `agent.eval()`，仍调用随机采样动作，视觉效果会受探索噪声影响。

当前脚本会从模型权重形状识别：

|          模型维度 | 自动环境            |
| ----------------: | ------------------- |
| 19 obs / 6 action | `UR5-v0`          |
| 28 obs / 7 action | `RM75-v0`         |
| 34 obs / 7 action | `RM75Approach-v0` |

并支持：

- `.cleanrl_model` 或完整 checkpoint；
- 相对/绝对模型路径；
- 确定性均值动作（默认）和 `--stochastic`；
- random/fixed 目标位置；
- fixed/random-cone 目标方向；
- viewer 或 `--headless` 统计评估；
- 距离、角度、成功、碰撞、超时、回报汇总；
- 目标切入方向可视化。

这解决了 UR5 模型被错误放进 34/7 网络而产生 size mismatch 的问题。它不改变已训练模型，只保证模型在匹配环境中被解释。

### 12.2 课程指标

| 指标                                   | 用途                               |
| -------------------------------------- | ---------------------------------- |
| `curriculum_stage`                   | 确认当前实际训练阶段               |
| `curriculum_mastery_rate`            | 最近 mastery window 当前阶段成功率 |
| `curriculum_promotion_threshold`     | 达到多少才允许晋级                 |

### 12.3 PPO 健康指标

| 指标                       | 正常解释                       | 警报                                                 |
| -------------------------- | ------------------------------ | ---------------------------------------------------- |
| `learning_rate`          | 控制每次参数更新幅度           | 太大导致 KL/clipfrac 长期高；太小后几乎不再学习      |
| `action_std_*`           | 当前实际探索噪声               | 太高难精确；太低过早停止探索                         |
| `action_saturation_rate` | 动作接近 ±1 的比例            | 长期很高说明策略不断要求超出动作范围                 |
| `approx_kl`              | 新旧策略变化量                 | 长期超过 target KL 表示更新过猛                      |
| `clipfrac`               | 被 PPO clip 的样本比例         | 长期很高表示步子过大；接近 0 且指标不变可能学习太弱  |
| `entropy`                | 策略分布不确定性               | 下降通常代表变确定；它不是“路径多样性”的直接度量   |
| `explained_variance`     | 价值网络解释 return 方差的程度 | 接近 1 较好；接近 0 预测帮助小；负值通常很差         |
| `value_loss`             | 价值预测误差                   | 只能在同奖励尺度内比较；突增常见于任务/课程突变      |
| `policy_loss`            | PPO surrogate 更新信号         | 正负值本身不代表成功，结合 KL、clipfrac 和任务指标看 |
| `SPS`                    | 每秒环境步                     | 只反映吞吐，不反映策略质量                           |

### 12.4 推荐看图顺序

1. `eval/strict_success_rate` 或点任务的 `eval/success_rate`；
2. `eval/collision_rate`；
3. final/min distance 与 angle；
4. curriculum stage 和 mastery；
5. training success/return/length；
6. KL、clipfrac、action std、explained variance；
7. SPS 和系统 GPU 指标。

GPU 利用率低不必自动判断训练配置错误：MuJoCo 单环境物理主要在 CPU，2×64 的网络很小，GPU 计算时间占比有限。

## 13. 平滑运动是怎样实现的，缺少什么

当前平滑性主要来自四层：

1. 策略输出的是每步关节目标**增量**，每维最大约 0.02 rad；
2. `q_target` 累积后经过关节限位；
3. MuJoCo position actuator 用 `kp/kv` 跟踪目标，不是瞬间把 `qpos` 改到目标；
4. 每个环境 step 执行 10 个物理子步，控制目标在子步内保持。

action std 后期下降也会让策略动作更确定，但它是探索噪声，不是速度限制。

目前**没有完整的实机运动学安全层**：

- 没有显式每关节速度上限投影；
- 没有加速度和 jerk 限制；
- 没有 action-rate penalty；
- 没有工作空间安全边界和急停控制器；
- MuJoCo 的 `kp/kv` 不是可直接复制到真实 RM75 控制器的参数。

因此“仿真看起来平滑”可以作为训练质量证据，但不是实机安全证明。以后真机前需要 trajectory filter/限速/限加速度/碰撞监控，而不是只调奖励。

## 15. 以后做新的强化学习机械臂项目，推荐复用的流程

### 阶段 A：先把仿真控制做对

1. 验证关节名、顺序、范围、执行器映射和 TCP；
2. 用零动作测试机械臂是否稳定；
3. 用人工小动作验证每一维动作控制哪个关节；
4. 明确一个 env step 的真实仿真时间；
5. 碰撞规则区分有效碰撞与相邻结构接触。

### 阶段 B：写清楚 MDP 契约

1. 任务成功必须依赖哪些状态？
2. 这些变量是否都在 observation 中？
3. action 是力矩、速度、绝对位置还是位置增量？
4. action 的无量纲范围如何映射到物理范围？
5. terminated 与 truncated 分别由什么触发？

### 阶段 C：从最小奖励开始

建议顺序：

```text
终点奖励 + 失败惩罚 + 时间成本
→ 稳定的势差进度
→ 必要的 one-shot 里程碑
→ 多目标任务的归一化联合误差
```

每次只改一个主要因素，并保存旧配置和固定评估结果。不要同时改奖励、学习率、目标分布和网络后仅凭一次曲线判断原因。

### 阶段 D：先建立评估，再长时间训练

至少保存：

- 最终 agent weights；
- latest full checkpoint；
- best full checkpoint 和 best weights；
- 固定种子 eval 指标；
- CLI 参数或配置文件；
- 代码版本/diff；
- 模型 observation/action 维度。

### 阶段 E：课程学习一次只改变一到两个难度轴

机械臂位姿任务的难度轴包括：目标区域、距离精度、角度精度、方向倾角、障碍、动力学扰动。一次同时收紧全部维度会让策略数据分布突变，很难区分是任务太难还是策略遗忘。

### 阶段 F：最终用严格指标验收

最终模型至少报告：

- 固定测试集成功率及置信区间；
- 碰撞率和超时率；
- 平均/分位数最终距离和角度；
- 平均成功步数；
- 不同目标区域/角度区间的分组成功率；
- 多个训练 seed，而不是只用 seed 1。

## 16. 当前项目的证据边界与下一步

### 已经被结果支持

- UR5 的动作/重置/PPO 稳定化能训练出有效点到点策略；
- RM75 7 轴环境、tracking error、自碰撞和里程碑能训练出接近 UR5 的点策略；
- RM75-V4 的 uniform 采样、适度碰撞权衡和 best evaluation 机制得到 84% 固定评估成功率、0% 碰撞；
- 位姿任务采用课程学习是必要方向，Stage 1 和 Stage 2 已经能获得明显非零成功。

### 尚未被结果支持

- 当前位姿奖励和课程能最终达到 Stage 6；
- 200 万或 400 万步本身足以得到最终随机位姿能力；
- 位姿模型已能完成真实抓取；
- 仿真动作平滑性可以直接迁移到真实 RM75。

### 当前 V7 快照应该怎样理解

截至 **2026-10-09 11:27（CST）** 读取的约 800k steps（训练仍可能继续，因此这只是快照）：

- 仍在 Stage 2；
- 固定评估当前阶段成功率约 63%，历史约 63–67%；
- Stage 2 晋级目标是 70%，尚未稳定达到；
- 固定评估碰撞率 0；
- strict success 仍为 0；
- 平均 final distance 约 11.9 cm、final angle 约 29.3°；
- ever direction success 已明显提升，但 ever final-position success 仍为 0，位置精度仍是主要瓶颈。

所以这版相对 V6 的 Stage-2 51–56% 平台有进步，但还不能称为最终位姿模型。后续判断是否继续训练，应以固定评估能否稳定跨过 70% 且 min/final distance 继续改善为依据，而不是只看 return。

## 18. 最终审查结论

这个项目从教学代码成长为实验系统的过程是合理的：最初几百行只需要“跑一次 PPO 并保存最终权重”，现在要支持两种机械臂、三种任务接口、多种训练恢复方式、课程、独立评估、最佳模型和完整诊断，行数必然增加。

真正可迁移的不是 `collision_penalty=45`、`action_scale=0.02` 或某一套阶段阈值，而是下面这些原则：

1. 策略动作空间与物理执行空间分离；
2. 观测必须让任务满足 Markov 性；
3. reward 提供方向明确、尺度稳定、不可重复刷取的信号；
4. 约束要在环境终止、控制限幅和评估指标中同时体现；
5. 训练曲线与固定独立评估分开；
6. 只加载权重的微调与完整断点续训分开；
7. 课程一次小幅增加难度，并防止阶段切换破坏 LR/探索；
8. 最终能力由严格任务指标证明，而不是由 return 或较宽松阶段 success 证明。

按这个标准，UR5-V3、RM75-V3 和 RM75-V4 的修改已经形成清晰的正向证据链；随机位姿系列的工程基础和诊断方式是合理的，但最终任务仍在训练验证阶段。这个区别应该在汇报、论文和之后的代码决策中始终保持清楚。
